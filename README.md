# 本地数字藏品登记与转让

在本机运行的数字藏品登记册：账户登记与停用、系列创建与封存、单件藏品
发行、基于期望版本的乐观并发转让，以及持有与历史查询。所有数据保存在
调用者指定的本机目录中，成功操作返回前已原子落盘。

## 使用

```bash
go test ./...
```

## 能力概览

入口在 `registry` 包：

- `Create(dir)` / `Open(dir)` / `Close()`：在指定数据位置新建、打开、
  关闭登记册。目录中没有数据时 `Open` 明确报错（不会当成空登记册），
  数据无法读取时返回 `ErrCorrupt`。同一目录同时只能被一个进程独占打开。
- 账户：`RegisterAccount` 唯一编号登记、`DeactivateAccount` 停用；
  停用后原有藏品与历史仍可查询，但不能发行、发起或接收转让。
- 系列：`CreateSeries`（记录创建账户与文字元数据）、`SealSeries`
  （仅创建账户可操作；封存后不能发行，已发行藏品仍可转让，不可撤销）。
- 发行 `Issue`：唯一藏品编号 + 系列 + 批次号 + 元数据 + 初始持有人；
  初始持有人必须已登记且可用，持有版本从 1 开始。
- 整批发行 `IssueBatch`：系列创建账户一次提交同一系列、同一批次号下
  的多件藏品（每件给出藏品编号、文字元数据与初始持有人），整批共用
  操作者、原因与请求号。成功后按提交顺序返回每件的编号、初始持有人、
  版本 1 与发行历史序号，历史序号连续递增，整批记录之间不会插入其他
  发行或转让；各件仍通过现有查询读取，随后可按现有规则转让、创建代转
  授权与计算版税。批次号继续作为发行标记，不同请求可沿用同一批次号。
  空清单、清单内编号重复或必填内容缺失按参数错误拒绝（文字元数据仍可
  为空）；操作者、系列或任一初始持有人未登记按对象不存在拒绝；非系列
  创建账户、系列已封存、操作者或初始持有人停用、任一藏品编号已占用
  沿用单件发行的对应业务拒绝，涉及某件时结果指出该件编号。整批拒绝是
  原子的：不新增任何藏品、持有或发行历史，尚未占用的编号仍可用于后续
  发行，未发行过的系列也不会因此固定版税规则；整批成功同样固定系列
  版税规则。请求号与单件发行等操作共用：内容与条目顺序相同的重复提交
  回放整批首次结果（成功或状态类拒绝）并标明重复，改动原因、系列、
  批次号、条目顺序或任一条目内容返回 `ErrRequestConflict`；并发整批
  提交同一请求只发行一次，与单件发行争用同一编号时最多一个请求占用。
- 转让 `Transfer`：当前持有人发起，接收人已登记、可用且不同于自己；
  必须给出期望持有人与期望版本，不符、藏品不存在或账户停用均明确拒绝，
  失败不改变持有、不产生历史。每次成功转让版本加 1。成交价款以分计
  （非负 int64，未填按 0，负数按参数错误拒绝），由持有人在转让时填写。
- 整批转让 `TransferBatch`：持有人一次提交多件藏品，分别转给各件指定
  的接收账户，整批共用操作者、原因与请求号；每件填写藏品编号、接收
  账户、期望持有人、期望版本及以分计的非负 int64 价款（未填按零）。
  藏品可来自不同系列和发行批次，接收账户可以重复，但操作者必须是每件
  的当前持有人。成功时按清单顺序返回每件的前后持有人、新版本、转让
  历史序号、价款、版税明细和余款；各件版本分别加一，历史序号连续，
  整批记录之间不能插入其他发行或转让。各件仍可通过现有持有、历史及
  应付查询核对，历史保留整批共用的操作者、原因和请求号。版税按各件
  所属系列的既定规则分别计算，同一收款账户在多件中出现也分别保留
  明细，不把价款合并后计算；零金额明细和余款归属沿用单件转让规则。
  整批只能全部成功或全部拒绝：空清单、重复藏品编号、必填内容缺失、
  非正期望版本或负价款按参数错误拒绝；每件沿用单件转让的账户登记、
  停用、收发不同人与持有版本规则，系列封存不阻止转让。多件存在业务
  拒绝时返回清单顺序最前的失败藏品及对应错误；操作者未登记或停用时
  只返回账户错误（不附藏品编号）。任何拒绝都不改变任何一件的持有、
  版本、历史或应付，也不消耗历史序号。整批转让不使用也不消耗代转
  授权；成功转出的藏品所绑定的旧版本授权，在藏品转回后仍不能恢复
  使用。请求号与已有操作共用同一操作者的范围：完全相同的内容及顺序
  重提回放首次成功或状态类拒绝并标明重复，改动原因、条目顺序或任一
  条目参数返回 `ErrRequestConflict`；参数错误及引用不存在不占用请求
  号。并发重复只能完成一次；整批与其他整批、单件转让或代转争用同一
  藏品版本时最多一方成功，失败整批中的其他藏品保持原状。操作者或
  接收账户停用先完成时整批拒绝，转让先完成时保留整批结果。整批持有
  变化、历史、应付与请求结果在同一临界区内一次落盘，保存失败不会
  留下部分转让；重开后用原请求重试只能得到原整批结果或完整执行一次，
  之后藏品再次易手或账户停用也不改变回放内容。状态类业务拒绝同样
  必须落盘后才成立：拒绝结果保存失败（原登记册仍可正常读取）时不
  返回业务拒绝，而与整批成功落盘失败一致返回明确的保存错误并保留
  实际写入错误——没有转让条目、没有失败藏品编号、不标为重复回放、
  结果中的业务错误为空，请求号不被占用，全部藏品的持有、版本、
  历史与版税应付保持提交前内容；保存恢复后用完全相同的请求重提按
  当前业务状态重新判断（状态已合法时正常执行，拒绝条件仍在时重新
  保存拒绝，保存成功后才返回对应业务错误）。参数错误与引用不存在
  不要求保存，存储暂时不可写时仍返回原错误。
- 版税规则与应付记录（只登记应付，不接入支付或账户余额）：
  - `SetRoyalty`：系列创建账户在首次发行前设置或清空版税规则（空规则
    表示不收版税），提交原因与请求号。每个收款账户只能出现一次且必须
    已登记、可用；比例是 1 至 10000 的整数（万分之一），合计不超过
    10000；重复账户或比例不合法按参数错误拒绝且原规则不变。首次成功
    发行后规则固定（未设置即固定为无版税，`ErrRoyaltyFrozen`），封存
    后同样拒绝；设置与首次发行同时发生时按先后次序生效。
  - 每笔成功转让按规则快照记录应付：各收款人金额分别按价款乘比例
    除以 10000 向下取整（零金额也保留明细，整个价款范围内准确），
    余款归转让前的持有人；代转价款在创建授权时确定、执行时不得改价，
    余款归授权人而非受托人。持有变化、历史、版税明细、请求结果与
    授权使用状态在同一临界区内一次落盘；失败不新增应付、不消耗授权。
    收款人可以同时是转让参与者；仅作为版税收款人的账户后来停用，
    不阻止新转让，也不删除其应付记录。
  - 查询：`GetSeriesRoyalty` 查当前规则，`RoyaltyHistory` 查每次变更
    的操作者、原因、请求号与前后内容；`TransferRoyalty` 按转让序号查
    计算依据与全部金额；`PayablesOf` 按收款账户查应付明细（按转让
    序号排列，无明细返回空列表）。
- 限时一次性代转授权：
  - `CreateAuthorization`：当前持有人为一件已发行藏品创建授权，指定
    唯一授权编号、受托账户、固定接收账户、绝对到期时间，并提交期望
    持有人与版本。受托人或接收人不能是授权人（返回 `ErrSameAccount`），
    受托人可与接收人相同；到期时间必须晚于当前时间（否则
    `ErrInvalidArgument`）。同一藏品可有多份授权，各自绑定创建时的
    持有版本；授权不改变持有关系，也不限制持有人继续直接转让。
  - `ProxyTransfer`：受托人凭授权发起代转，藏品与接收人均以授权记载
    为准。成功后持有人变为接收人、版本加一，授权记为已使用并关联该
    笔转让；代转同样出现在藏品 `History` 中，操作者为实际受托账户，
    历史条目的 `AuthID` 可追溯授权。非受托人（`ErrForbidden`）、已
    撤销（`ErrAuthorizationRevoked`）、已到期
    （`ErrAuthorizationExpired`，到期时间点起即不可用）、已使用
    （`ErrAuthorizationUsed`）分别明确拒绝；授权人、受托人或接收人
    任一停用返回 `ErrAccountInactive`；持有版本已变化返回
    `ErrConflict`——即使藏品后来回到原授权人手中，旧授权也不恢复。
  - `RevokeAuthorization`：仅授权人可撤销尚未使用的授权；已撤销后
    再次撤销不增加记录（幂等），已使用时拒绝撤销。
  - 查询：`GetAuthorization` 按编号返回授权内容与当前状态
    （active/revoked/expired/used，到期按当前时间实时判断）；
    `AuthorizationHistory` 按藏品查看创建、撤销、使用记录中的操作者、
    原因、请求号与前后状态。
- 藏品拆分意向（只记录未来拆分的约定，不改变藏品编号、持有人、持有
  版本与版税应付，既有发行、转让与代转功能不受影响）：
  - `CreateSplitIntent`：当前持有人登记拆分意向，指定唯一意向编号、
    藏品、期望持有人与版本、绝对到期时间，以及至少两个账户和各自
    份额（万分之一整数，每份 1..10000，合计必须为 10000，账户不能
    重复）。发起人与参与账户都须已登记且可用，到期时间须晚于当前
    时间；发起人可以列入方案，其份额在创建时视为已同意。参数不合法
    或对象不存在时拒绝且不占用请求号；编号已用、账户停用、持有版本
    不符分别明确拒绝。系列封存不妨碍登记意向；藏品已有仍有效的待
    确认或已达成意向时，新建按状态冲突（`ErrConflict`）拒绝。方案
    创建后不能修改。
  - `AnswerSplitIntent`：待确认或已达成且仍有效时，参与账户可同意
    或拒绝自己的份额；全部同意显示已达成，任一拒绝显示已拒绝。
    重复相同答复成功但不新增记录，改答拒绝（`ErrSplitAnswered`）；
    名单外账户无权答复（`ErrForbidden`）。
  - `WithdrawSplitIntent`：仅发起人可撤回仍有效的待确认或已达成
    意向；已拒绝不能撤回，已撤回再次撤回成功但不增加记录（幂等）。
  - 状态：待确认/已达成之外，已拒绝与已撤回是落盘终态，不再接受
    答复；其余意向在藏品持有版本变化，或发起人、任一参与账户停用
    后显示已失效（藏品转回原持有人也不能恢复），没有上述失效条件
    时从到期时间点起显示已过期。已失效或已过期时拒绝答复及撤回并
    说明原因；结束的意向仍可查询，并允许当前持有人用新编号另建
    方案。
  - 查询：`GetSplitIntent` 按编号查看方案、各方答复与当前状态；
    `SplitIntentHistory` 按藏品查看意向历史（创建、首次答复、撤回
    各记录意向编号、操作者、原因、请求号、时间与前后状态，按发生
    顺序排列；重复答复与重复撤回不新增记录）。
- 查询：`GetAccount` / `GetSeries` / `GetItem` / `GetHolding` /
  `HoldingsOf` / `History`。不存在的对象返回包裹 `ErrNotFound` 的错误；
  历史按顺序包含发行与历次成功转让（含代转）的操作者、原因、前后持有
  人与版本，发行前的持有人与版本为空。
- 幂等：单件与整批发行、单件与整批转让、创建/撤销授权、代转、版税规则设置与拆分意向的
  创建/答复/撤回都需要操作者、原因、请求号；同一操作者的请求号在全部操作间共用。相同业务参数重提
  返回首次的成功结果或状态类业务拒绝（成功代转即使在到期、停用或再次
  易手后重提，仍返回原转让结果；成交价款与规则内容参与参数判定，改价
  或改规则按请求号冲突拒绝；拆分意向仅调整份额名单排列视为相同内容），
  任一参数改变返回 `ErrRequestConflict`，
  并发重复提交只生效一次。参数错误与引用不存在不占用请求号。
- 持久化：每次操作在同一临界区内修改状态并以临时文件 + fsync + 原子
  rename 落盘，进程被直接终止后重开，登记、停用、封存、持有、授权、
  授权变更记录、版税规则与应付明细、拆分意向与意向变更记录、请求结果
  与历史都完整保留，不会
  出现"已换人却没有对应历史"的中间状态。未收到结果的请求可用原请求号
  重试，返回已保存结果或完整执行一次。旧版本数据可直接打开，原历史
  不变，旧请求仍可回放，旧成交按价款 0 查询且不补造应付明细。

## 错误判定

业务错误均为哨兵（`errors.Is` 判定）：`ErrNotFound`、`ErrAlreadyExists`、
`ErrAccountInactive`、`ErrSeriesSealed`、`ErrConflict`、`ErrSameAccount`、
`ErrForbidden`、`ErrAuthorizationRevoked`、`ErrAuthorizationExpired`、
`ErrAuthorizationUsed`、`ErrRoyaltyFrozen`、`ErrSplitIntentRejected`、
`ErrSplitIntentWithdrawn`、`ErrSplitIntentInvalid`、`ErrSplitIntentExpired`、
`ErrSplitAnswered`、`ErrRequestConflict`、`ErrInvalidArgument`、
`ErrCorrupt`、`ErrLocked`。
